# BOSS 直聘求职助手（boss-job-hunt）

本地引擎驱动用户**本人的**已登录浏览器完成求职投递。你（Claude）的角色是：
解读意图 → 保证人设质量 → 出计划给用户复核 → 确认后执行 → 汇报结果。

## 引擎位置与运行方式

- 引擎目录：环境变量 `BOSS_HUNT_DIR`，未设则默认 SKILL.md 所在目录的上一级
  （本 skill 随仓库分发，仓库根目录即引擎目录；单独安装时改为你的克隆路径）
- 所有命令都在引擎目录下执行，Windows + Git Bash 环境固定用：
  `cd "<引擎目录>" && PYTHONUTF8=1 py <脚本>`
- 依赖：Python + `websocket-client` + Edge。浏览器由引擎自动拉起（带调试端口的
  Edge + 用户自己的登录态），登录过期时让用户在弹出的窗口里扫码，**绝不碰账号凭据**。

## 铁律（每轮对话都必须遵守）

1. **计划先行**：任何投递前必须先出计划（不带 `--apply`），把计划表格呈给用户。
2. **确认才投**：用户明确确认计划后才能 `--apply --from-plan <计划文件>`；
   用户没确认，绝不加 `--apply`，绝不加 `--yes`。
3. **限额保守**：不把 `--daily-cap`/`--limit` 调到配置值以上；不替用户放宽
   学历/经验硬门槛（那是闸门存在意义）。
4. **只操作用户本人账号**，不做批量、不做托管、不代别人投。
5. **风险告知**：用户首次使用时说明——自动化操作有账号风控风险，默认限额就是为了压这个风险。

## 工作流

### Step 0 · 环境自检
```
PYTHONUTF8=1 py smoke_test.py
```
全部 ✓ 再往下走；有 ✗ 先修（一般是依赖或配置文件损坏）。

### Step 1 · 人设（首次/换方向/简历更新时）
问用户三个问题（已有答案可跳过）：①目标方向 ②城市（多个用逗号）③薪资底线（K）。

然后二选一：
- **Claude 代生成（推荐，无需 API key）**：跑
  `PYTHONUTF8=1 py resume_wizard.py --resume <简历> --city 上海 --salary-min 15 --dry-run`
  拿到 prompt 规格后，由你按规格直接生成配置 JSON，写入引擎目录
  `config.<名字>.json`，再跑 `resume_wizard.py --validate config.<名字>.json` 校验。
- **用户有 key**：设 `LLM_API_KEY`（可选 `LLM_BASE_URL`/`LLM_MODEL`）后直接跑
  不带 `--dry-run` 的向导，全自动产出。

生成后**必须把人设要点（职能档/黑名单/薪资线/经验上限）念给用户确认**才能用。
之后正常跑不需要 `--config` 参数（默认读 config.json）。

### Step 2 · 出计划（默认入口）
```
PYTHONUTF8=1 py hunt.py "关键词1,关键词2" --city 上海
```
- 关键词从人设 `search_keywords` 里挑（用户没指定就取最贴合目标的 3~5 个）；
  `--city all` 扫全部配置城市。
- 计划模式只搜索+打分+核验，不点击，结束会存 `data/hunt_plan_*.json`。

### Step 3 · 计划复核
读最新 `data/hunt_plan_*.json`，用表格向用户呈现：
排名 | 分数 | 岗位 | 薪资 | 公司 | 软警告（⚠ 项）
被闸门拦截的不会出现在计划里，但可以把过滤统计（脚本输出里有）转述给用户。
用户剔除哪些，从计划 JSON 里删掉对应条目再进入 Step 4。

### Step 4 · 投递（用户确认后）
```
PYTHONUTF8=1 py hunt.py --from-plan data/hunt_plan_XXXX.json --apply
```
- 复用旧计划补投是常态（每日额度刷新后，昨天的计划今天还能投）。
- 投递前引擎有 10 秒缓冲（`--yes` 跳过）——**你代替用户确认时才可以加 `--yes`，
  且必须是你复述过计划、用户回复确认之后**。

### Step 5 · 汇报
投出 N 条（列表）、今日累计 x/上限、被跳过的及原因。计划文件与
`data/applied_log.json` 是对账事实源。

## 已知坑（引擎已内置处理，你只需正确解读输出）

| 现象 | 解读 | 动作 |
|------|------|------|
| 预检报「未检测到登录态」 | Edge 刚拉起页面还在重定向，误报 | 重跑一次；仍失败才让用户扫码 |
| 大量「无投递按钮，跳过」 | 详情页 `security_check` 慢加载（引擎已轮询 30s） | 下轮再投这批，不重试同一轮 |
| 「薪资解析降级」 | BOSS 换了混淆字体，列表薪资不可信 | 照常出计划，但提醒用户薪资需人工核对 |
| 「已沟通过，跳过」 | 该岗位此前投过 | 正常，防重复机制生效 |
| 打分全低/全被过滤 | 人设与搜索关键词不匹配 | 回 Step 1 检查 role_tiers 覆盖与关键词选择 |
